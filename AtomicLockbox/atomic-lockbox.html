Tamper-evident chunks

Argon2id derives a 256-bit key. XChaCha20-Poly1305 authenticates the header and every 4 MiB chunk before decryption can commit.

03

Staged replacement

The browser keeps staged bytes invisible until close, then attempts one complete replacement. Cancellation and failed authentication abort before commit.

Security and format notes

Format. PWCRYPT v1 stores a 96-byte authenticated header, a 16-byte header tag, then independently authenticated chunks. The header records the exact original byte length, salt, nonce prefix, chunk size, and Argon2id parameters. Filenames and timestamps are not hidden.

Limits. Atomic replacement is the browser and filesystem’s best-effort commit behavior, not secure erasure or a power-loss durability guarantee. Backups, snapshots, journals, SSD wear leveling, cloud history, and temporary artifacts may retain old data. A native tool is required for stronger guarantees.

Compatibility. Direct local-file replacement requires the File System Access API in a top-level secure context. Current desktop Chrome and Edge are the intended browsers. An ordinary file upload control cannot safely overwrite its source path.

Password safety. Password guessing can happen offline, so use a long, unique passphrase. JavaScript strings, browser memory, and operating-system caches cannot be reliably wiped. This utility deliberately offers no reset, escrow, or recovery path.

Atomic Lockbox is a self-contained local utility. Review and keep this HTML file alongside the data format you intend to preserve.
